# 浏览器会话安全迁移

## 已实现
- 新网页登录通过 X-CN-Session-Mode: cookie 请求会话；登录 JSON 只返回非敏感 cn-cookie-session 标记，不返回真实会话凭证。
- 客户凭证使用 __Host-cn-client，管理员使用 __Host-cn-admin。均为 Secure / HttpOnly / SameSite=Strict / Path=/，不设置 Domain。
- Cookie 写操作必须具备自定义会话请求头，并核对 Origin / Sec-Fetch-Site；跨站写入继续由 Worker 和业务层分别拒绝。
- Cookie 模式的账号级限流仍以真实服务端会话为维度计数，不使用公开状态标记。
- 后台安全再验证在事务内签发新会话并撤销旧会话，不延长原会话到期时间；不记录密码或动态验证码。
- 显式退出清 Cookie 并撤销会话。手机离开/刷新时撤销旧会话，后台注销响应不清 Cookie，避免迟到响应删除之后的新登录。
- 手机镜像仍通过隔离的父窗口通道操作，不读取管理员 Cookie，不复制客户登录凭证。

## 兼容边界
- 已存在的显式 Bearer 客户端/会话仍兼容；新的网页登录不再把真实凭证写到 localStorage。旧页面已有的 Bearer 凭证在下次重新登录后才被标记替换，不进行全站强制注销，不修改正式客户密码。
- 新版和旧版前端不可混合发布。若回滚整个 Worker，Cookie 安全能力也随版本回退，应要求用户重新打开页面登录。
- HttpOnly 降低脚本读取凭证的风险，不能阻止已执行的恶意脚本代用户发请求；CSP 收紧和独立安全审计仍需继续。
- 当前没有启用新的 WAF/Access 服务，没有更改域名、绑定、路由或数据库结构。

## 测试
新增 qa/browser-sessions.cjs 验证 Cookie 属性、登录响应不暴露凭证、三端实际 Cookie 登录、脚本不可读、客户/管理员隔离、CSRF、重复 Cookie 拒绝、退出撤销、后台凭证轮换、原到期时间保持、后台迟到注销不清新 Cookie。
qa/sessions.cjs 从隔离浏览器上下文读取 Cookie 验证服务端真正撤销，不以公开标记代替凭证验证。
完整回归仍检查注册、密码找回、基金/IPO/大宗交易、审批、消息、镜像与账务一致性。

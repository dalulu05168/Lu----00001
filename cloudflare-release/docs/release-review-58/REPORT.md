## 预发布验证要求

在 Cloudflare 创建独立预发服务与测试域名，绑定独立测试 Neon 分支或 PostgreSQL。先通过管理侧确认数据库身份，再写入合成数据。只用测试密钥和测试管理员，生产两域名保持原映射。预发定时任务必须与生产隔离。

当前 Worker 对 Host 有明确分流，仅 workers.dev 单域访问不足以证明客户与后台行为。预发需两个测试 Host 的受控映射，验证电脑/手机 UA 分流、登录与后台入口，以及客户域名不能访问后台接口。

预发还需验证目标兼容日期、静态资源与 logo、ready、注册与密码重置、TOTP、Cookie 恢复和退出、过期、资金两级审批及重复拒绝、订单幂等与权限隔离，并记录云预发版本 ID、资产清单、构建摘要及退出码。现有本地 PGlite 结果与云预发结果独立列示。

## 数据库、备份与发布步骤

候选与生产源码基线的迁移文件无变化，无新增迁移要求。发布前用只读授权核对生产实际 schema_migrations、账户、资金申请、审计、回执、订单、持仓和账本约束，确认与当前生产相容。不要执行未启用的 migration-trade-evidence 或重放历史全量迁移。

正式发布前，由数据库负责人记录恢复点和保留窗口，生成加密逻辑备份、计算摘要，并恢复到新隔离分支验证约束及对账。生产备份与恢复点目前未验证。既有本地备份恢复结果仅证明隔离夹具。

1. 导出 Cloudflare 当前版本与实际流量比例、模块与资产引用、域名/路由、绑定名与类型、runtime、Observability 和 cron。核对源提交和候选摘要。密钥仅由账户侧安全配置管理。
2. 核验独立云预发通过。以测试资产清单及 Worker 摘要形成正式评审包，保持旧生产 release-manifest 作为历史记录。正式上传前再检查源和产物一致。
3. 审查发布工具后再执行。现有 publish-existing.cjs 默认 keep_assets 且只上传模块，候选的桌面、登录和共享样式产物已变化，不能假设沿用旧资产足够。旧 publish-verified.cjs 有历史路径与 schema 门禁，应按实际目标评审。必须明确资产上传/引用方案，完整保留实际绑定和调度配置。
4. 提交旧版本、拟上传新版本、资产引用、数据库只读核对和预发证据供最终批准。获得批准后另行上传版本与切流。切流前重新确认生产配置未漂移。
5. 上线后对正式客户域名分别用桌面和手机 UA 核对入口、共享样式和资产指纹，对后台域名核对登录及工作台。检查 ready、匿名拒绝、错误率、审计及资金异常告警。真实客户资金与订单写验收继续留在隔离预发。

## 回滚

回滚目标以切流前控制平面实时快照为准。将流量恢复到旧版本及原比例，同时核验原资产引用、双域名、runtime、绑定、cron、ready 和匿名访问控制。版本回滚不撤销业务数据。

若出现资金或会话故障，暂停相关操作并保存日志，按订单、流水、审计和回执对账。旧版审批重复请求返回 400，阶段防重不同，审核人员须刷新并逐笔核对待处理状态。PITR 或数据库恢复需要单独批准和写入窗口评估，避免覆盖切流期间真实交易。
